1. Executive Summary
The Halopesa MiniApp Platform enables third-party partners to seamlessly integrate their MiniApps into the Halopesa ecosystem.
Through this integration model:
* MiniApps are embedded within the Halopesa mobile application via a secure SDK container
* Partner backend systems integrate directly with Halopesa backend services for authentication, payment initialization, and transaction management
* Payments are executed through the Halopesa Wallet using a secure, token-based mechanism
* Transaction results are synchronized via backend callbacks and partner-initiated notifications
This architecture ensures:
* Secure and controlled payment execution through backend orchestration
* Clear separation of responsibilities between platform and partner systems
* High reliability via verification, callback, and reconciliation mechanisms

4.2.2 HostApp to MiniApp - Seamless Login Integration (LinkToken-based Auto Login)
Purpose
To provide a seamless user experience, MiniApps may implement LinkToken-based Auto Login, allowing users to access the MiniApp without repeated authentication.
Flow Overview
1. User logs in to MiniApp for the first time.
2. Partner Backend generates a LinkToken.
3. Partner Backend IPN the LinkToken to Halopesa Backend.
4. Halopesa Backend securely stores the LinkToken.
5. On subsequent launches, Halopesa App passes the LinkToken to MiniApp.
6. MiniApp validates the LinkToken with Partner Backend.
7. If validation succeeds, the user is automatically authenticated.
8. If validation fails or expires, MiniApp falls back to the standard login flow.
Responsibilities
Component
	Responsibility
	Partner Backend
	Generate, validate, revoke and manage LinkToken lifecycle
	MiniApp
	Perform auto-login validation
	Halopesa Backend
	Securely store LinkToken and pass it to MiniApp during launch
	Launch Context Example
{
  "msisdn": "123456",
  "linkToken": "eyJhbGciOiJIUzI1NiIs..."
}
Sequence Diagram
  

Failure Handling
MiniApp MUST fall back to the standard login flow if:
* LinkToken is expired.
* LinkToken is revoked.
* LinkToken validation fails.
* Partner authentication service is unavailable.
API Detailed Design
POST /ewallet3/ewallet-business-adapter/api/v1/miniapp/oauth/client-link-token

  "expiredAt": "2026-12-31T23:59:59Z"
}
Field
	Type
	Required
	Description
	msisdn
	String
	Yes
	Partner user identifier
	linkToken
	String
	Yes
	Auto-login token generated by Partner Backend
	expiredAt
	ISO8601
	No
	LinkToken expiration timestamp
	Success Response
{
  "code": "SUCCESS",
  "message": "LinkToken registered successfully"
}
Notes
* LinkToken MUST uniquely identify a user within a MiniApp.
* LinkToken MUST contain iss field for identifying the principal created and digitally signed the token 
* LinkToken SHOULD be transmitted only through HTTPS.
* Halopesa stores LinkToken as an opaque value and does not validate its content.
* Partner Backend remains the source of truth for LinkToken validation.
* LinkToken expiration and revocation are managed by Partner Backend.

4.4 Payment Process & Transaction Handling 
After the customer confirms payment:
* Halopesa processes the transaction asynchronously
* Halopesa sends payment result via IPN callback
* partner backend performs fulfillment processing
Partners MUST:
* implement IPN callback endpoint
* support idempotent IPN processing
* avoid duplicate fulfillment
* support asynchronous transaction handling
* support transaction reconciliation
Partner Payment Result Callback API (IPN)
Purpose
Halopesa uses this API to asynchronously notify partner systems about the final payment processing result.
This API is designed for:
* asynchronous transaction handling
* eventual consistency
* retry-safe delivery
* idempotent fulfillment processing
Security Model
This API uses:
* HTTPS/TLS
* IP whitelist validation
* HMAC signature authentication
OAuth2 authentication is NOT required for inbound callback APIs.
API Definition

2. Validate timestamp

5.1.1 MiniApp Initialization
Purpose
Initialize the MiniApp runtime environment inside the Halopesa application.
Flow
1. Customer selects a MiniApp service icon within Halopesa App
2. Halopesa App passes these information to the SDK initialization layer:
   * serviceCode
   * partnerCode
3. SDK validates and resolves the configured MiniApp information
4. SDK retrieves corresponding MiniApp configuration:
   * MiniApp URL
   * runtime configuration
   * capability configuration
   * permission policies
5. If MiniApp configuration exists:
   * SDK opens the corresponding MiniApp
   * SDK initializes runtime environment
   * SDK injects trusted runtime context into MiniApp Frontend
6. If configuration does not exist:
   * SDK displays service unavailable message
Injected Runtime Context
The SDK may inject:
* user context
* runtime configuration
* permission-based capabilities
* locale information
* communication bridge APIs

5.3 Important Transaction Semantics 
A successful response from:
/ewallet3/ewallet-business-customer/api/v1/app/transfer/w2w/confirm
DOES NOT indicate final transaction success.
It only indicates that the payment request has been accepted for asynchronous processing.
Final transaction status MUST be determined via:
* IPN callback
* transaction inquiry API
If partner fulfillment fails after successful payment processing, the partner system is responsible for triggering refund processing through Halopesa refund APIs.
