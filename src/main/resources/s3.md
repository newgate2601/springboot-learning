# Amazon S3 (Simple Storage Service) — Tổng hợp kiến thức

---

## 1. S3 là gì?

Amazon S3 là dịch vụ **lưu trữ đối tượng (object storage)** trên cloud của AWS.  
Thay vì lưu file theo cấu trúc thư mục như ổ cứng thông thường, S3 lưu dữ liệu dưới dạng **object** trong các **bucket**.

```
Cấu trúc cơ bản:
Bucket (tên duy nhất toàn cầu)
  └── Object (file + metadata + unique key)
        ├── Key:   "images/avatar/user123.png"
        ├── Value: [binary data]
        └── Metadata: content-type, size, tags...
```

---

## 2. Bucket, Object, Key, Value, Metadata

### Bucket
- Là **container** chứa toàn bộ objects
- Gắn cố định với **1 region** — không thể đổi sau khi tạo
- Mỗi AWS account tối đa **100 buckets** (có thể tăng lên 1000)

---

### Object

Mỗi file upload lên S3 = 1 **Object**, gồm 4 thành phần:

```
┌─────────────────────────────────────────────┐
│                  OBJECT                      │
├──────────────┬──────────────────────────────┤
│ Key          │ "images/users/avatar123.png"  │
├──────────────┼──────────────────────────────┤
│ Value        │ [binary data của file]        │
├──────────────┼──────────────────────────────┤
│ Metadata     │ content-type, size, tags...   │
├──────────────┼──────────────────────────────┤
│ Version ID   │ "xK9mN2..." (nếu bật version)│
└──────────────┴──────────────────────────────┘
```

---

### Key
- Là **định danh duy nhất** của object trong bucket
- Không có folder thật — key chỉ là **một chuỗi string**

```
Key = "images/users/avatar123.png"
Full URL = https://{bucket}.s3.{region}.amazonaws.com/{key}
```

---

### Value
- Là **nội dung thực của file** — raw bytes
- Tối đa **5TB** mỗi object
- Upload > 5GB phải dùng **Multipart Upload**

---

### Metadata

| Loại | Mô tả | Ví dụ |
|---|---|---|
| **System Metadata** | AWS tự set | Content-Type, Content-Length, ETag, Last-Modified |
| **User Metadata** | Tự định nghĩa (prefix `x-amz-meta-`) | `x-amz-meta-uploaded-by: user456` |

> ⚠️ Metadata **không thể thay đổi sau khi upload** — muốn đổi phải copy object sang object mới.

## 3. Không phải File System — Không có Directory thật

### Sự thật về "folder" trong S3

```
❌ Bạn NGHĨ S3 có cấu trúc folder thật sự
✅ Thực tế S3 chỉ là FLAT LIST các key:
   "images/users/avatar.png"
   "docs/report.pdf"
```

**"Folder" chỉ là prefix trong key string** — AWS Console tự parse `/` để hiển thị như folder, nhưng thực tế không tồn tại.

### Hệ quả thực tế

```
# Xóa "folder" → tìm tất cả keys có prefix đó → xóa từng object một
# Rename folder → copy toàn bộ sang key mới → xóa key cũ
# Tạo folder rỗng → S3 tạo object key = "images/" với value rỗng (0 byte)
```

### So sánh S3 vs Ổ đĩa thông thường

| | Ổ đĩa (EBS/Local) | S3 |
|---|---|---|
| Protocol | Block I/O / POSIX | HTTP REST API |
| Append file | ✅ | ❌ Phải GET → modify → PUT |
| Random access | ✅ | ❌ chỉ byte-range GET |
| Latency | Microseconds | Milliseconds |

## 4. Tạo Bucket trên AWS Console — Chi tiết từng setting

### 4.1 General Configuration

#### AWS Region
- Bucket gắn cố định với 1 region, **không đổi được sau khi tạo**
- Chọn region gần user để giảm latency
- Ảnh hưởng đến **data residency** (pháp lý)

#### Bucket Namespace

| | Global Namespace | Account Regional Namespace ✅ |
|---|---|---|
| Unique scope | Toàn cầu | Trong account + region của bạn |
| Bảo mật | Tên bucket lộ ra ngoài | Account khác không thấy tên |
| Rủi ro | Bị "name squat" | Không bị conflict |
| Khuyến nghị | ❌ | ✅ |

#### Bucket Name (Account Regional Namespace)

```
Bucket name prefix:                excel-test
Account Regional namespace suffix: -150914615641-ap-southeast-2-an
                                    ↑             ↑              ↑
                                 Account ID    Region      "an" = account namespace

Full bucket name: excel-test-150914615641-ap-southeast-2-an
```

**Quy tắc đặt tên prefix:**
```
✅ 3–63 ký tự (kết hợp với suffix ≤ 63)
✅ Chỉ dùng: chữ thường, số, dấu gạch ngang (-)
✅ Bắt đầu bằng chữ hoặc số
❌ Không dùng chữ hoa, dấu gạch dưới (_), dấu chấm (.)
❌ Không được là IP address format
⚠️ Tên KHÔNG thể sửa sau khi tạo bucket
```

#### Copy settings from existing bucket *(optional)*
- Sao chép cấu hình từ bucket có sẵn
- Format: `s3://bucket/prefix`

### 4.2 Object Ownership

Kiểm soát **ai sở hữu object** khi được write từ account AWS khác.

| | ACLs disabled ✅ | ACLs enabled |
|---|---|---|
| Ownership | Luôn thuộc bucket owner | Có thể thuộc account khác |
| Access control | Chỉ qua Bucket Policy / IAM | Policy + ACL |
| Độ phức tạp | Đơn giản | Phức tạp, legacy |
| Khuyến nghị | ✅ Best practice | ⚠️ Chỉ dùng khi cần cross-account ACL cũ |

> Khi chọn ACLs disabled → **Object Ownership = "Bucket owner enforced"**

---

### 4.3 Block Public Access Settings ⭐ (Rất quan trọng)

4 settings độc lập — tick "Block all public access" = bật cả 4:

| # | Setting | Tác dụng |
|---|---|---|
| 1 | Block public access via **new** ACLs | Chặn ACL MỚI grant public, không ảnh hưởng ACL cũ |
| 2 | Block public access via **any** ACLs | Ignore TẤT CẢ ACL (cũ + mới) grant public |
| 3 | Block public access via **new** bucket/access point policies | Chặn policy MỚI grant public |
| 4 | Block public and cross-account access via **any** policies | Ignore TẤT CẢ policy (cũ + mới) grant public |

```
✅ Bật tất cả (default — 99% use case):
   → Bucket private hoàn toàn
   → Serve content qua Presigned URL hoặc CloudFront

⚠️ Tắt (cẩn thận):
   → Chỉ khi host static website PUBLIC
   → Lý do phổ biến nhất gây data leak trên S3
```

### 4.4 Bucket Versioning

Khi bật, **mỗi lần PUT/DELETE** tạo version mới thay vì ghi đè.

```
Versioning OFF:
  upload lần 2 → ghi đè lần 1 (MẤT)

Versioning ON:
  upload lần 1 → [VersionId: "AAA"]
  upload lần 2 → [VersionId: "BBB"] ← current
                  [VersionId: "AAA"] ← vẫn còn

DELETE với versioning:
  → Tạo "Delete Marker", KHÔNG xóa thật
  → Các version cũ vẫn còn, có thể restore

Trạng thái:
  Unversioned → chưa bật bao giờ
  Enabled     → đang bật
  Suspended   → đã tắt (version cũ vẫn còn)

⚠️ Một khi đã bật, KHÔNG THỂ về Unversioned
⚠️ Bắt buộc Enable nếu dùng Object Lock
```

**AWS CLI:**
```bash
aws s3api put-bucket-versioning \
  --bucket my-bucket \
  --versioning-configuration Status=Enabled
```

### 4.6 Default Encryption ⭐

Server-side encryption **tự động áp dụng** cho mọi object mới trong bucket.

#### 3 loại Encryption Type:

| Type | Key quản lý bởi | Chi phí | Dùng khi |
|---|---|---|---|
| **SSE-S3** (default) | AWS hoàn toàn | Miễn phí | 90% use case |
| **SSE-KMS** | AWS KMS (bạn kiểm soát) | Thêm KMS cost | Compliance, audit trail |
| **DSSE-KMS** | AWS KMS (2 lớp) | Cao nhất | Regulated industries |

```
SSE-S3:
  → AES-256, AWS tự quản lý key
  → Không có audit trail chi tiết
  → ✅ Đơn giản, đủ dùng cho hầu hết trường hợp

SSE-KMS:
  → Bạn tự quản lý key trong AWS KMS
  → CloudTrail log mọi lần dùng key → audit trail đầy đủ
  → Có thể rotate key, set key policy riêng
  → Chi phí: ~$0.03/10,000 KMS API calls
  → ✅ HIPAA, PCI-DSS, SOC 2 compliance

DSSE-KMS:
  → 2 lớp encryption độc lập
  → Chi phí cao nhất (2x KMS calls)
  → ✅ Extra security cho regulated industries
```

#### Bucket Key

```
Không có Bucket Key:
  Mỗi object upload → 1 KMS API call → tốn tiền
  1,000,000 objects = 1,000,000 KMS calls = ~$30

Có Bucket Key (Enable — recommended):
  S3 tạo 1 data key từ KMS → cache ở bucket level
  Dùng data key đó encrypt nhiều objects
  → Giảm ~99% KMS API calls → tiết kiệm chi phí lớn

⚠️ Bucket Key KHÔNG hỗ trợ DSSE-KMS
```

### 4.7 Advanced Settings — Object Lock

**WORM model: Write Once Read Many**

```
Một khi đã lock → object KHÔNG THỂ:
  ❌ Bị xóa (kể cả root account ở Compliance mode)
  ❌ Bị ghi đè
  ❌ Bị thay đổi
→ Trong khoảng thời gian đã định (hoặc vĩnh viễn)
```

#### 2 chế độ Lock:

| Mode | Ai có thể bypass? | Dùng khi |
|---|---|---|
| **Governance** | User có quyền đặc biệt | Test policy, không quá strict |
| **Compliance** | KHÔNG AI (kể cả root) | Compliance bắt buộc (SEC, FINRA...) |

#### Retention:

```
Fixed period: Lock trong N ngày/năm → tự động unlock sau
Legal Hold:   Lock vô thời hạn → phải manually remove
```

#### Use cases:
```
✅ Financial records (yêu cầu giữ 7 năm)
✅ Medical records (HIPAA)
✅ Audit logs không được phép xóa
✅ Backup chống ransomware
✅ Legal documents
```

> ⚠️ Phải bật lúc **tạo bucket** — không bật sau được  
> ⚠️ Bắt buộc **Versioning = Enable**

## 8. Presigned URLs

### Vấn đề giải quyết

```
❌ Không có Presigned URL:
User ──[file 50MB]──► Server ──[file 50MB]──► S3  (Bottleneck)

✅ Có Presigned URL:
User ──[xin phép]──► Server ──[tạo URL]──► S3
User ◄──[presigned URL]──── Server
User ──[upload thẳng 50MB]──────────────► S3
```

### Cơ chế Auth

URL chứa **chữ ký HMAC-SHA256** — ai có URL đều dùng được, không cần AWS account.

```
https://bucket.s3.region.amazonaws.com/key
  ?X-Amz-Algorithm=AWS4-HMAC-SHA256
  &X-Amz-Credential=AKID/date/region/s3/aws4_request
  &X-Amz-Date=...
  &X-Amz-Expires=3600
  &X-Amz-Signature=abc123...
```

**S3 verify:**
```
1. Parse Access Key ID → tìm Secret Key trong IAM
2. Tính lại Signature → so sánh
3. Kiểm tra Expires
4. Kiểm tra IAM permission của người tạo URL
→ Allow hoặc Deny
```

> ⚠️ Permission của URL = Permission của **người tạo URL**  
> Revoke IAM quyền → URL cũ cũng không dùng được nữa

### Flow Upload (PUT)

```
Client ──POST /get-upload-url──► Server (validate + generate URL)
Client ◄──{ uploadUrl, fileKey }── Server
Client ──PUT file thẳng──────────────────────► S3
Client ──POST /confirm-upload──► Server (lưu DB)
```

### Flow Download (GET)

```
Client ──GET /files/123──► Server (check permission + generate URL)
Client ◄──{ url }───────── Server
Client ──GET thẳng từ S3 bằng URL──────────► S3
```

### Code thực tế

```python
import boto3, uuid
from botocore.config import Config

s3_client = boto3.client('s3', region_name='ap-southeast-1',
    config=Config(signature_version='s3v4'))

# PUT URL (upload)
def generate_upload_url(file_type, folder="uploads"):
    file_key = f"{folder}/{uuid.uuid4()}.{file_type.split('/')[-1]}"
    url = s3_client.generate_presigned_url(
        ClientMethod='put_object',
        Params={ 'Bucket': 'my-bucket', 'Key': file_key, 'ContentType': file_type },
        ExpiresIn=300, HttpMethod='PUT'
    )
    return { "upload_url": url, "file_key": file_key }

# GET URL (download)
def generate_download_url(file_key, expires_in=900):
    return s3_client.generate_presigned_url(
        ClientMethod='get_object',
        Params={ 'Bucket': 'my-bucket', 'Key': file_key },
        ExpiresIn=expires_in
    )
```

```javascript
// Client upload
const { upload_url, file_key } = await fetch('/api/get-upload-url', {
  method: 'POST',
  body: JSON.stringify({ fileType: file.type }),
  headers: { 'Content-Type': 'application/json' }
}).then(r => r.json());

await fetch(upload_url, {
  method: 'PUT', body: file,
  headers: { 'Content-Type': file.type }
});
```

### Use Cases

| Use Case | Expire | Ghi chú |
|---|---|---|
| Avatar upload | 5 phút | PUT URL |
| Document view (private) | 15 phút | GET URL, check permission trước |
| Video upload lớn | 30 phút | Kết hợp Multipart Upload |
| Export CSV lớn | 1 giờ | Server gen → upload S3 → trả URL |
| Chia sẻ file tạm | 7 ngày | Như WeTransfer |

### Bảo mật

```
✅ NÊN:
   - Validate file type/size ở server TRƯỚC khi tạo URL
   - Expire ngắn nhất có thể
   - Dùng IAM Role thay vì IAM User
   - Enforce ContentType trong Params
   - Lưu file_key vào DB chỉ sau khi confirm

❌ KHÔNG:
   - Generate URL phía client (lộ credentials)
   - Expire quá dài cho upload URL
   - Để bucket public để tránh dùng presigned URL
```

### Presigned URL vs CloudFront Signed URL

| | Presigned URL (S3) | CloudFront Signed URL |
|---|---|---|
| Truy cập | Thẳng S3 | Qua CDN |
| Cache | ❌ | ✅ |
| Restriction | Expire only | Expire + IP |
| Dùng cho | Upload | Serve media private |

```
BUCKET (General config + Security settings)
│  ├── Region: ap-southeast-2
│  ├── Namespace: Account Regional (recommended)
│  ├── Block Public Access: ON ✅
│  ├── Object Ownership: ACLs disabled ✅

├── Object: "logs/2025/app.log"
│     ├── Storage Class: STANDARD → (30d) IA → (90d) GLACIER → (365d) DELETE
```
